# Multi-level parallel pipeline: итоговый отчёт

1. **Архитектура.** PSIMpy submitter/monitor поддерживает bounded execution queue; Manager динамически раздаёт ordinary export-spatial shards через прежний pull scheduler. Каждый worker выполняет одну SDK extraction; durable prepared queue и один uploader работают независимо. Downloader/validator и пользовательский consumer перекрываются с SDK.
2. **PSIMpy.** Добавлены ParallelExport/export_spatial_parallel, session manifest/summary, completion-order и deterministic readers, independent reusable downloader transports, owner locks для local/mounted storage. Версия пакета 0.3.1. Worker и Manager имеют assembly version1.1.0.0 для проверки установки; Contracts/protocol остаются1.0. Старые APIs сохранены.
3. **Manager.** Scheduler сохранён; добавлены multicore correctness/fairness tests, safe pinned-export requeue, stale AssignmentId protection, additive protobuf diagnostics/status fields, optional worker-measured processing time и GET /statistics в существующем binding. Квоты/целостность/persistence сохранены.
4. **Worker.** SDK executor отделён от PreparedArtifactPipeline. Подготовка подтверждается независимо от занятого uploader; heartbeat прекращается после подтверждения Manager. Durable spool/owner lock сохранены, terminal deliveries удерживаются для диагностики, поздний ACK не создаёт удалённый state заново.
5. **Eligible pool.** Online/non-UNREGISTERED worker, export-spatial + spatial-binary-v2 и точный TargetModelKey в AvailableModelKeys. Normal affinity отсутствует. Manager объявляет upload/download-v2. Готовые remote results можно восстановить и без online workers; новая сессия без eligible workers отвергается.
6. **Sharding.** Один pin ModelVersionUtc до selection; explicit composite ElementIds нормализуются и глобально дедуплицируются disk-backed index с сохранением первого порядка. Default 1000 IDs/request: 38 748 уникальных IDs дают 39 shards. У каждого собственные TaskId/ClientRequestId/path и одна дата snapshot.
7. **Defaults.** SDK=1/worker; shard=1000; task_prefetch=max(2,2×eligible), cap128; download_workers=2 (1–4); result_prefetch=max(2,2×download_workers); uploader=1/worker; chunks in flight=3; prepared artifacts=2; prepared bytes=16 GiB, ограничены общей spool quota. Python output quota64 GiB, selection scratch1 GiB, max sources10m.
8. **Backpressure.** Prepared count включает текущий upload; до нового SDK резервируется worst-case MaxArtifactBytes. При полном spool worker поддерживает heartbeat и ждёт. Python разделяет execution и delivery buffers; inflight жёстко ограничен их суммой. Неопределённый accepted-but-unacknowledged submit не освобождает очередь для новых tasks. Финальные READY файлы ограничены output quota, не хранят geometry в RAM.
9. **Resume.** Durable manifest/selection/idempotency keys сохраняются до RPC. READY файлы повторно проверяются и переиспользуются, unfinished TaskId/download продолжаются. TASK_EXPIRED/result TTL пересоздают только affected shard с прежним pin и новым attempt-path. Временная FAILED ошибка может быть восстановлена новым запуском с отдельным bounded retry budget и накопительной RetryCount. close — пауза; cancel — отмена с сохранением unresolved cancellation IDs/requests. Snapshot mismatch/изменённая immutable identity не принимаются молча.
10. **Добавленные tests.** Multi-worker queue20/4, fast/slow pull, capability/model filters, soft preference, lease loss, stale reservations, concurrent uploads/global quotas, SDK/upload overlap, spool count/bytes, reconnect/identity/terminal retention, legacy protobuf readers, measured-duration persistence. Python покрывает out-of-order, retry/TTL/restart/cancel, lost replies, separate buffers, bounded downloads, full mesh duplication/coordinates, manifest concurrency и unsupported advisory-lock filesystem.
11. **Выполненные checks.** 132 Python, 49 .NET integration, 16 .NET unit — passed, skip0. Включены hard Python-process crash/restart (пять повторов фиксированного empty-journal window), повторное использование TaskId/READY mtime, C# binary writer→Python interop и PSIMpy→настоящий Manager/store/writer/uploader/pipeline с fake SDK. Реальные WPF worker, native stdio adapter и PSIMpy wheel собраны. Контракты совпадают. У worker остались три прежних warning locations: два deprecated SDK properties в ModelCatalog и неинициализированное поле Menu._fileProvider; новые compile errors отсутствуют.
12. **Synthetic scaling.** 18 shards, fake SDK1s + upload300ms + download300ms. 1 worker=18.914s; 2=9.830s (1.92×); 3=7.158s (2.64×). Ideal SDK pipeline18.6/9.6/6.6s; полностью последовательная сумма стадий28.8s — расчётная, не production measurement. Download peak≤2. Подробности: parallel-scaling.json.
13. **Оставшиеся риски.** Реальный speedup ограничен SDK geometry variance, общим disk/SHA и каналом. IncludeMeshes=true повторяет определения между shards (измеряется mesh_duplication; rewrite/cache нет). TTL/квоты должны соответствовать размеру и длительности передачи. Native SDK может блокировать свой UI вызов до возврата; отмена кооперативная. WorkerProcessingWallMs — измеренная operation wall, включая encoding/write-finalize, не SDK active; network/upload/retry в неё не входят. SDK active остаётся unavailable. При host-local lock fallback нельзя параллельно писать один Drive-каталог из разных Colab VM.
14. **Проверка двух реальных машин.** В согласованное окно установить обновления, проверить разные DurableWorkerId/owner locks, совместимые Pilot/SDK versions, одинаковую модель и snapshot. Начать с небольшого IncludeMeshes=false, сверить geometry с одиночным export; убедиться в разных workers, SDK concurrency1 и queue2. Затем отключить один worker/transport, перезапустить Python с тем же каталогом и проверить requeue/resume; после этого full meshes, repeated buffer bytes, квоты, SHA/disk и cancellation. Автоматические tests не запускали реальный Pilot SDK extraction и не обновляли рабочий Colab.
